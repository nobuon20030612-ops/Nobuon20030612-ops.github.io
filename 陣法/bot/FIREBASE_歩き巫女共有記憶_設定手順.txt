歩き巫女 Firebase共有記憶 v2.5 設定手順
更新日: 2026-07-28

==================================================
目的
==================================================
歩き巫女が無料公開Webで一度調べた一般知識をCloud Firestoreへ共有保存し、
別の利用者・別ブラウザでも同じ調査結果を再利用できるようにする。

重要:
・陣法検索、DB、Worker、計算本体とは完全に独立。
・Firebaseが未設定/障害/無料枠到達でもBotはlocalStorageへ自動フォールバック。
・生チャット全文はFirestoreへ保存しない。
・v2.5で共有保存するのはWikipediaから取得した公開知識だけ。

==================================================
1. Firebaseプロジェクト
==================================================
既にFirebaseを利用しているGoogleアカウントでOK。
既存コンテンツとは分けて「歩き巫女」専用プロジェクトを新規作成することを推奨。

料金プラン:
・Sparkのまま
・Cloud Billingをリンクしない
・Blazeへ変更しない

Google Analyticsはこの用途では不要。OFFのままでよい。

==================================================
2. Webアプリを登録
==================================================
Firebaseコンソール → プロジェクト概要 → Web(</>) → アプリを登録。
例: arukimiko-web

表示される firebaseConfig を控える。

==================================================
3. Authentication
==================================================
Firebaseコンソール → Authentication → Sign-in method
→ Anonymous（匿名）を有効化。

歩き巫女はログイン画面を出さず、共有記憶を使う時だけ匿名認証する。

==================================================
4. Cloud Firestore
==================================================
Firestore Databaseを作成。
日本中心のサイトなら、作成時に選択できる場合は Tokyo (asia-northeast1) が近い。
Firestoreのロケーションは後から簡単に変更できないので確認して作成する。

作成後、Rulesタブへ
「FIREBASE_歩き巫女共有記憶_firestore.rules」
の内容をそのまま貼り付けて公開する。

※テストモードの「誰でも読み書き可能」は使用しない。

==================================================
5. サイト側firebaseConfig
==================================================
陣法/陣法/jinpo-bot-firebase-config.js を開く。

enabled:false
を

enabled:true

へ変更。

firebaseConfig:{ ... }
の中へFirebaseコンソールで表示されたWebアプリ設定を貼り付ける。

例:
  firebaseConfig:{
    apiKey:'...',
    authDomain:'....firebaseapp.com',
    projectId:'...',
    storageBucket:'...',
    messagingSenderId:'...',
    appId:'...'
  }

Firebase WebのfirebaseConfigは秘密鍵ではない。
Firestoreの保護はSecurity Rulesと、必要に応じてApp Checkで行う。

==================================================
6. ローカル確認
==================================================
Live Server等でサイトを開く。

チャットで:
「Firebase共有記憶の状態どう？」

未設定:
「共有記憶はまだFirebase未設定…」

正常接続後:
「Firebase共有記憶は接続できている…」

一般知識を1回調べる:
「富士山について調べて」

別ブラウザ/シークレットウィンドウから同じ質問をすると、
Firestoreに有効な共有記憶があればWeb再取得前に共有記憶を利用する。

==================================================
7. App Check（本番公開前の推奨）
==================================================
初回のローカル確認ではOFFのままでよい。

App Checkを設定する場合:
・FirebaseコンソールでWebアプリをApp Checkへ登録
・reCAPTCHA v3のsite keyを取得
・jinpo-bot-firebase-config.js の
  appCheck.enabled:true
  siteKey:'...'
  へ設定

いきなりFirestore側で強制(enforcement)せず、まずFirebaseコンソールの
App Checkメトリクスを確認して正規アクセスが通ることを確認してから有効化する。

==================================================
共有記憶の安全設計
==================================================
・Firestoreへ生チャット全文を保存しない
・現在はWikipedia由来の回答だけ保存可能
・同じ検索語は期間バケットごとに決め打ちdocument IDを使用
・Firestore Rulesでupdate/delete禁止
・一覧取得(list)禁止
・1件取得(get)だけ許可
・Firebase停止時はlocalStorageへ自動退避
・Firebaseのために陣法検索を待たせない設計

==================================================
今後
==================================================
広島カープ専用の最新情報を共有記憶へ保存する場合は、
NPB公式/広島東洋カープ公式など許可する公開ソースを決めたうえで
Firestore RulesのURL/source許可リストも同時に拡張する。
